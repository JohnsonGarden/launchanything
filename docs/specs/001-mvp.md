# SDD-001 — LaunchAnything v0.1: per-app proxy launch

Status: **Implementation slice — macOS runtime verification required**
Target: macOS 12+; architecture: Tauri 2, Rust, Swift AppKit bridge, React 19, TypeScript, shadcn-style UI.

## Problem

A macOS user of Shadowrocket/Clash currently needs multiple app-specific proxy launchers. A uniform launcher should save per-app launch configurations without affecting system-wide proxy settings.

## Jobs to be done

- Pick a `.app`, give it a name and bind it to a saved HTTP/SOCKS5 endpoint.
- Launch the app and see whether macOS confirmed the new process.
- Check whether the configured TCP proxy port is reachable before launch.
- Compare launch methods without assuming the OS enforces all application traffic.
- Preserve configuration across restarts without using a cloud service.

## Functional contract

| ID | Requirement | Acceptance |
|---|---|---|
| F-01 | Reusable proxy profiles | Create, edit, delete; restrict removal while assigned; keep one profile. |
| F-02 | App configuration | Create, edit, remove `.app` references without touching original bundles. |
| F-03 | Env launch | Pass uppercase and lowercase `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, optional `NO_PROXY`. SOCKS5 uses `socks5h` for compatible clients. |
| F-04 | Chromium launch | Supply `--proxy-server` and `--proxy-bypass-list` parameters. |
| F-05 | Combined launch | Supply both environment and Chromium flags without a shell. |
| F-06 | Safe failure | Reject startup if proxy TCP port unreachable or target app already running. |
| F-07 | Launch outcome | Return a PID upon successful LaunchServices callback; provide explicit errors otherwise. |
| F-08 | Storage | Versioned local JSON, saved atomically; preserve invalid files. |
| F-09 | User interface | Accessible apps, profiles, editors, search ⌘K and add ⌘N. |
| F-10 | Security | No telemetry, elevated permissions, shell interpolation or secret storage. |

## Acceptance scenarios

**A. HTTP env:** Environment variables correctly describe the saved HTTP endpoint; macOS confirms process launch.

**B. SOCKS5 combined:** IPv6 `::1` endpoint uses `socks5h://[::1]:1080` in env and `--proxy-server=socks5://[::1]:1080` in args.

**C. Offline:** Proxy port closed; launch rejects without starting the app.

**D. Already running:** Target already running; shows explicit quit-first error.

**E. Durable:** App and profile configs survive restart; corrupt JSON is preserved.

**F. Safe removal:** Removing an entry never deletes original `.app` files.

## Out of scope

Universal per-app traffic capture; automatic proxy discovery; credential storage; PAC/WPAD; background daemon; menu bar; global proxy changes; DNS leak guarantees; code signing and notarization. App Sandbox may not be used for this launch mechanism because macOS ignores caller-supplied environment when the calling process is sandboxed. Real proxy enforcement requires separate Network Extension investigation.

## Known limitations

- App may ignore env and flags, use direct sockets, or redirect through an existing helper process. PID is not proof of proxied traffic.
- TCP port test does not verify SOCKS/HTTP handshake, authentication, DNS or exit IP.
- Some native dialogs show `.app` bundles as directories; manual absolute paths are supported.
- No auto-discovery or port auto-switching from proxy clients in this version.
